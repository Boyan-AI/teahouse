同一个局域网里，每台电脑启动茶话间，就能自动看见彼此，点开就能发消息、传文件。全程不碰外网、不依赖任何服务器，数据只在内网里走。适合公司内网、隔离网、实验室这类不方便、或者根本不允许连外网的环境。

## 为什么做这个

内网里传个文件、说句话，本该是小事，可挑来挑去没一个顺手的：

- **飞鸽** 这类好用的商业工具需要付费；
- **内网通** 仅提供 Windows 版本，统信 UOS 与 Mac 无法直接安装；
- **iptux** 虽跨平台但界面上手门槛偏高，日常办公使用不够直观。

干脆自己写一个：免费开源、纯内网直连、从 Windows 7 到国产统信 UOS 再到 macOS 全平台覆盖、打开就会用。这就是茶话间。

## 特性

- **打开就用，零配置发现** —— UDP 广播自动发现同网段在线同事，节点直连通信，无需架设服务器或手动输入 IP。
- **跨网段与局域网更新** —— 支持手动添加对端 IP 与 CIDR 网段探测；已保存网段在在线节点间低频自动共享；支持全局网段扫描与实时进度；支持局域网内 P2P 索包自更新。
- **即时通信与群组协作** —— 支持单聊与讨论组群聊；支持文本、本地图片、截图粘贴、Twemoji SVG 图形表情与自定义表情收藏；具备消息送达确认、离线暂存与上线自动补发、2 分钟内撤回、消息转发、引用回复直达原消息、群内 @ 成员；支持群简介（≤200 字）与群公告（≤1024 字）同步广播；支持窗口震动提醒。
- **高速点对点文件传输** —— TCP 点对点直连，跑满局域网物理带宽；支持单文件、多选文件及完整文件夹发送，支持断点续传与传输历史记录；提供 24 小时领取时效机制，超期自动关闭接收。
- **共享文件柜（主界面第三页签）** —— 主窗口原生集成共享文件柜；支持发布本地文件夹，配置全局默认权限（关闭 / 只读 / 允许读写）与按联系人独立授权；支持分页浏览同事文件柜、面包屑导航、多选下载与另存为；在具备权限时可直接拖拽上传文件或文件夹，统一归档在独立子目录，避免覆盖他人数据；提供最近上传汇总。
- **独立大图浏览与内置离线 OCR** —— 独立看图窗口支持平滑缩放、双击锚点缩放、旋转与窗口居中；支持在当前会话图片历史中连续切换上一张 / 下一张；内置 PaddleOCR（PP-OCRv6 tiny + onnxruntime-web WASM）纯离线文字识别引擎，支持在原图文字位置直接拖选、跨行选择与复制文本，附带快捷复制全部文字；具备会话级内存缓存，重复查看秒级恢复文字层。
- **原生截图工具** —— 快捷键一键唤起；支持矩形选择、画笔、箭头、马赛克与原地单行文字标注；提供放大镜与取色坐标预览；适配 Linux Wayland 与 X11 环境。
- **屏幕协助（只查看）** —— 私聊头部发起查看，对方每次同意并选屏；独立窗口支持自动调节及 3/5/10 帧档位，可随时停止。纯内网明文传输；当前已完成本地回环与 Electron 合成画面验证，各系统的物理屏幕权限与性能仍待实机验收，详见[技术边界](docs/tech-design.md#remote-view)。
- **本地历史与全文检索** —— 基于 SQLite WAL 模式与 FTS 全文索引，支持全局快速搜索联系人、群聊与聊天记录；支持单会话内历史消息搜索；支持聊天数据本地导出备份与换机迁移。
- **多语言即时切换** —— 原生支持简体中文与 English，在「设置 → 通用 → 语言 / Language」一键切换并即时同步全窗口；新安装根据系统首选语言自动初始化。
- **纯内网安全边界** —— 启动时全局注入 `--no-proxy-server` 禁用环境代理；彻底杜绝外网请求、统计上报与第三方 CDN 依赖；渲染层开启严格沙箱与上下文隔离；网络报文全程白名单校验；接收文件名执行路径穿越清洗；内联图片限制单边 ≤8192px 且总像素 ≤3200 万；日志脱敏处理，消息正文与文件内容绝不入日志。

## 安装

前往 [**Releases**](https://github.com/skyjt/teahouse/releases) 下载对应平台的安装包。

**Windows** — 根据系统架构选择 x64 或 ia32（32 位）NSIS 安装包，也可直接使用对应便携版。Windows 7 需安装 **SP1**；若启用了代码签名，未打补丁的 Win7 需先安装系统更新 KB4474419。

**Linux** — `.deb` 适用于 Debian / Ubuntu / 统信 UOS / 麒麟等；其他发行版可用 `AppImage`（赋予可执行权限后运行）：

```bash
chmod +x Teahouse-*.AppImage
./Teahouse-*.AppImage
```

**macOS** — 打开 `.dmg` 拖入「应用程序」。内网分发若未签名 / 公证，首次打开需在「系统设置 → 隐私与安全性」中允许，或在终端执行：

```bash
xattr -dr com.apple.quarantine /Applications/Teahouse.app
```

## 使用

1. 同一局域网内的设备各自启动茶话间，会通过 UDP 广播自动相互发现并出现在左侧列表中。
2. 点击联系人即可开始单聊，或点击加号新建多人讨论组；将文件或文件夹拖入聊天窗口即可发送。
3. 点击左侧导航栏的「文件柜」页签，可浏览同事开放共享的文件，或发布本机的共享文件夹并分配权限。
4. **跨网段通信**：当 UDP 广播无法穿透不同路由网段时，可在「设置 → 网络」中手动添加对端 IP 或配置 CIDR 网段探测；已保存的网段会在在线同事间低频自动共享；点击导航栏底部的刷新按钮可一键扫描全部网段并查看实时进度。
5. **图片查看与文字提取**：双击聊天图片打开独立看图窗口，点击两侧箭头可连续浏览该会话历史图片；点击下方「识别文字」即可在图内直接划选文字并复制。
6. 首次运行时操作系统防火墙若弹出放行提示，请允许通行（默认端口：UDP `17878` 与 TCP `17879`）。

**讨论组快捷操作**：输入 `@` 后可选择成员，列表末尾提供“所有人”；输入 `@全体`、`@全体成员` 或 `@all` 可将该候选置顶。必须选择候选才能发送真正的提及提醒，仅输入同名文字不会自动提醒全体。旧版客户端可能不识别全体提醒，建议群成员使用一致的新版本。点击群消息或成员列表中其他成员的头像，可选择“@该成员”或“发起私聊”；已离群成员不可再提及，未知联系人不提供私聊入口。本人发出的普通消息显示设置中的昵称与头像。

## 工作原理

每个客户端都是平等的对等节点（P2P），整个系统**不设立中心服务器**：

```text
渲染进程 (Renderer) —— 会话列表 / 聊天面板 / 共享文件柜 / 图片查看器 / 设置窗口
   │  仅通过 contextBridge 暴露的安全 IPC 契约通信
主进程 (Main)
   ├─ 网络服务 (Net)   : UDP 广播发现与心跳、UDP+ACK / TCP 消息通道、TCP 文件直传
   ├─ 业务服务 (Services): 联系人管理、群组服务、共享文件柜服务、离线暂存队列
   ├─ 存储层   (Store) : SQLite (WAL 模式 + FTS 全文索引，持久化消息、群组、授权与传输记录)
   └─ 系统集成 (System): 系统托盘、桌面通知、全局快捷键、内置 OCR 调度与窗口管理
```

| 通道 / 模块 | 传输方式 | 默认端口 | 主要用途 |
|---|---|---|---|
| 节点发现 | UDP 广播 / 单播 | 17878 | 上线广播、在线应答、心跳保活、离线通知与共享网段交换 |
| 控制与短消息 | UDP + ACK 重传 | 17878 | 文本消息、送达回执、撤回指令、窗口震动、群控制、文件柜元数据 |
| 长文本通道 | TCP 直连 | 17879 | 超过 UDP MTU 大小的超长文本消息回退通道 |
| 文件与数据传输 | TCP 直连 | 17879 | 文件与文件夹分块校验直传、文件柜数据上行与下行、局域网 P2P 自更新包拉取 |

节点发现机制参考 IP Messenger 的上线广播与应答思想，通信协议采用自主设计的 UTF-8 JSON 格式，独立于传统 ipmsg 协议。

## 安全性

- **网络边界明确** —— 所有通信严格限制在局域网内部；启动时全局追加 `--no-proxy-server` 阻断系统与环境代理；应用内零外部请求、零数据上报、零自动检查更新。
- **最小化攻击面** —— 渲染进程仅加载本地受控打包资源，杜绝远程页面注入；强制开启 `contextIsolation` 与 Chromium 沙箱，禁用 `nodeIntegration`；全局拦截页面跳转与新窗口创建；配置严格的内容安全策略（CSP）。
- **不可信输入防护** —— 网络层接收的所有报文均执行严格的格式与长度白名单校验；对未知报文类型采取平滑忽略策略，保证安全性与向前兼容；聊天内联图片实行单边 ≤8192px 且总像素 ≤3200 万的边界校验，避免解码引起内存溢出。
- **本地落盘防护** —— 接收文件名执行全路径穿越清洗；文件保存严格落在用户指定目录或隔离子目录，采用重名自动编号处理，杜绝覆盖既有文件；文件柜上传仅允许写入对方指定的独立子目录。
- **运行日志脱敏** —— 消息正文与传输文件内容绝不写入任何日志文件，仅记录消息 ID、状态码、文件体积等基础审计元数据。
- **物理内网信任模型** —— 沿用 IP Messenger / iptux 等经典工具的局域网明文传输模型，适合在边界受控的公司内网、隔离办公区或专用实验室网络中运行。


## 诊断与反馈（v0.60.0 起）

遇到问题后，打开 **设置 → 关于 → 诊断与反馈 → 导出诊断包**，选择本机保存位置，再手动把 ZIP 附到 Issue。“复制环境信息”可补充问题描述。请注明发生时间、操作步骤和预期结果；文件/图片传输问题建议双方分别导出，并标明发送端、接收端。

诊断包包含版本、系统/架构/桌面环境、已知监听/权限状态与近期运行记录。日志最多保留 **7 天、10 MiB**，不记录聊天正文、文件名/内容、屏幕画面、剪贴板内容、凭据或原始错误正文。默认匿名化节点与网络地址；“附带真实网络地址”默认关闭，勾选后附上**本次运行**观察到的地址映射，公开附件前请确认可以公开。复制环境信息始终脱敏，应用不会自动上传或连接外网。

应用打不开时，可从下列位置取 `logs` 目录中的 `.jsonl` 文件；不要上传整个数据目录、数据库或 `identity-salt`。正常重启也能导出上一轮保留的日志。“未正常退出”仅表示上次关闭未完成，原生崩溃或突然断电可能没有完整堆栈。

| 平台 | 默认日志目录 |
|---|---|
| Windows | `%APPDATA%\茶话间\logs` |
| Linux / UOS / 麒麟 | `${XDG_CONFIG_HOME:-~/.config}/茶话间/logs` |
| macOS | `~/Library/Application Support/茶话间/logs` |

开发实例覆盖 `PANTRY_USER_DATA` 时使用该目录的 `logs` 子目录。目录不可写时仅保留受限内存记录，摘要注明持久化失败；退出后内存记录无法恢复。日志只记录关键阶段，无逐帧记录或常驻性能监测，打包线程仅在导出时运行。

## 内网 Agent 与棋类 PK

### 软件内创建 Agent

点击联系人搜索栏旁的 **AI**，打开 **Agent 管理**，填写名字、人设、内网服务根地址、模型 ID 和密钥，勾选启用并保存。编辑时密钥留空表示保留；取消启用后保存即停止。最多同时配置 8 个 Agent。

- 接口采用 **Anthropic Messages 兼容协议**；例如填写 `http://192.168.1.10:8000`，应用请求 `/v1/messages`。代理前缀可填在根地址后，不要重复填写 `/v1` 或 `/v1/messages`。
- 只接受字面 IPv4 的 `10/8`、`172.16/12`、`192.168/16` 私网和 `127/8` 回环地址，不接受公网、域名、URL 凭证或重定向。HTTPS 验证证书，不绕过证书错误；HTTP 不加密，请仅在可信内网使用。
- Agent 以稳定独立节点身份出现在联系人中，可私聊或通过现有成员邀请加入讨论组。群内必须明确 `@该 Agent` 才回复；仅 `@所有人`、其他 Agent 发言不会触发。移出单个群沿用现有群权限。
- 由创建者客户端托管，关闭棋盘/管理窗不停止 Agent；禁用、删除、退出应用或休眠会取消在途调用。休眠恢复后按启用配置重新启动。删除保留已有聊天历史与离线联系人记录，不会暗中清空他人的记录。
- 密钥不进入联系人资料、群元数据、日志或界面列表。macOS/Windows 可用时使用系统加密存储；安全后端不可验证（包括当前 Electron22 的 Linux 场景）仅放在内存，重启后须重填。创建者本地保留人设、配置和 Agent 独立聊天数据库。
- 模型只收到该 Agent 的当前私聊/明确群提及及有限回复上下文，不上传未提及的整群历史。每 Agent 串行请求，最多排队 8 条、32 个会话上下文、12 条上下文消息；请求总截止 60 秒、最多生成 1024 tokens，响应体上限 64 KiB，聊天回复上限 4096 UTF-8 字节。没有工具执行、外网搜索或后台自主行动。
- SDK 的 `DEBUG=true` 可能泄露请求和密钥，应用在此情况下拒绝模型调用。界面与聊天显示的是脱敏错误。

### 图文消息与 AI 引用

选择、拖入或粘贴图片后，图片先进入待发送附件；输入说明后一起发送。文字附在首张图片上，是同一条图文消息，不会先单独发送一条文字。多张图片仍逐张发送，不是相册。私聊和群聊都可引用文字或图片；图片右键菜单提供“引用回复”。转发图文保留说明，但不会把原会话的引用 ID 或提及意图带到新会话。旧版客户端可能只显示图片，建议参与端同步升级。

- AI 接收真实图片的 base64 数据和说明，使用配置的 Anthropic 兼容接口；内网模型必须支持视觉，接口拒绝时显示明确错误，不会悄悄改为纯文本识图。
- AI 当前图片限 PNG/JPEG/GIF/WebP、单图 5 MiB，沿用最大边 8192、最多 3200 万像素门禁。每个 Agent 的本地图片缓存和接收预留预算为 128 MiB；失败传输的预留在下次启用时按实际磁盘缓存重算，不自动删除缓存。普通文件不送入模型。
- 引用由 Agent 从自己已收到的同会话消息解析，不接受发送方提供的“引用原文”；引用不存在、跨会话或已撤回时明确标记不可用。图片未接收完成或不可用时明确提示，不递归读取引用链。
- 群图文仍须明确提及该 AI 才请求模型；未提及的群图片只保留在 Agent 本机，供之后显式引用，不会因此上传整群历史。模型已收到的内容不能通过事后撤回从模型服务端收回；旧有有限文字上下文也不等同于服务端数据擦除。

### 表情收藏管理

在聊天“表情包”网格第一格点击齿轮设置按钮，打开独立管理窗口；没有收藏时也保留入口。支持导入本地图片、拖动排序、左右移动按钮、Alt + 左右键、全选和批量删除。顺序自动保存，聊天发送面板实时同步，重新打开仍保留；右键收藏不再直接删除。

删除需确认，**仅移除收藏索引，不清空聊天记录，也不删除历史/在途消息可能仍引用的本地素材**，因此不是磁盘空间清理或安全擦除。没有商店、云同步或外网下载。

### 五子棋与中国象棋

私聊或讨论组中打开 **PK** 菜单，选择 **五子棋** 或 **中国象棋**。创建者打开独立棋盘，对方收到邀请卡并主动点击进入；再次从同一聊天的同棋种 PK 入口进入时优先复用有效房间，不重复创建。需要至少一位支持棋盘协议的在线成员，旧版客户端不会被强行弹窗。

- 入场默认旁观，可选黑/白或红/黑座位；两人入座后，由任一入座玩家点击 **开始对局**；旁观者不能代开。满座后其他成员只能旁观，不能落子。原私聊双方或当前群成员才可加入。
- 五子棋：15×15、无禁手、五连及以上获胜。中国象棋：马腿/象眼/河界/九宫/炮架/将帅照面/自陷将军均校验，将死和困毙均判负；三次相同轮次局面判和，不采用专业竞赛长将长捉裁定。
- 对弈中离座或关闭棋盘需确认，视为认输。获胜、和棋或认输后弹出结果：双方都选择 **再来一局** 才重开；**结束** 只退出本人的棋盘。旁观者可继续等待下一局或结束旁观，不影响其他成员。
- 房主节点裁定座位和盘面；重复/乱序请求、抢座和旁观越权在主进程复核。房主退出应用或被判定离线后房间结束，不迁移房主；单房间最长两小时，每客户端最多保留 32 个房间。
- 邀请保留在聊天历史；历史邀请仍需在线房间与成员资格校验，不能恢复已经结束的房间。邀请不是原骰子/猜拳的随机结果，原有玩法保持不变。

### 消息 Markdown 展示

聊天正文支持加粗、斜体、删除线、标题、列表、引用、行内/围栏代码、简单表格和 HTTP(S) 链接；无需切换编辑模式。Agent 正文中的字面 `\n` 兼容为换行，代码片段与 Windows 路径保留字面内容，普通消息不做这种转义转换。消息原文仍用于存储、复制和转发。

仅支持有限 Markdown 子集，不执行 HTML/脚本，也不加载消息里的远程图片（Markdown 图片仅显示说明文字）。代码块和宽表格在消息内部滚动，链接沿用现有受控打开通道。棋局邀请是带邀请者、棋种和房间标识的专用卡片，点击 **加入对局 / 旁观** 即可进入。

开发验收：先 `npm run build`，再 `npm run test:extensions`。该脚本启动三个隔离 Electron 客户端，仅使用回环网络验证实际获胜、双方重开、旁观、邀请卡、头像、Agent 表单，以及本地模型 mock 经生产 SDK/Agent/P2P 显示 Markdown、真实粘贴图文、图片引用、表情管理窗拖动/键盘排序、重开持久化、跨窗同步和确认/批量删除（确认返回值由隔离测试代答）的完整链路；截图和结果保存在 `out/extension-ui-*`，不调用真实模型。
